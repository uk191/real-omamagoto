# C-0.1 P0 再設計・構築報告

2026-10-17。実プレイによる「退屈、何をすればよいかわからない、集計表を読んでいる」という評価を受け、生活が自動で進み、必要なときに選ぶ体験へ変更した。

## 状態と接続の監査

`13_family` の条件付き生成 → `16_recovery` の初期家計・就業 → `18_monthly_v02` の月次状態と意思決定 → `21_child_b11` の暦日接続 → 旧 `22_experience_c0/c0.Game` → 新 `23_experience_c01/c01.Experience` → プレイヤー専用API → ブラウザ。

A/Bの係数・統計核・APIは変更していない。旧C-0も変更せず、新しい体験層を独立追加した。保存済み旧リリースとの194実装・核ファイルのハッシュ比較を `reports/inherited_code_verification.json` に残した。UIの表示や文章演出は科学モデルの乱数を消費しない。同じ家庭・seed・行動履歴の科学状態が旧Gameと一致する検査を行う。

月次会計の確定済み `A_transactions` から現金移動を集計する。資産振替と借入を入金収入に混ぜない。元本返済は現金支払に入り、発生ベース費用とは区別する。現金差は入金−支払＋資産振替＋借入に一致する。未決算の最終途中月について、前の決算をもう一度当期収支として表示しない。

居住環境は自治体の人口密度によるゲーム用の分類であり、自宅の緑地・交通・近所を観測したものではない。都市4,000人/km²以上、郊外・地方都市300以上4,000未満、低密度300未満。Aの完全な条件付き家庭を生成してから密度条件で棄却抽出し、選ばれた家庭の住宅・所得を後から変更しない。48候補で確認できなければ明示的エラーにする。狭い条件の生成限界は、現実の存在不可能性と区別する。学歴は既存の4区分、就業は有無の条件で、雇用形態の細分類を選べると偽装しない。

## 選べる行動と、実際の影響

| 場面・選択 | A/Bへ渡す処理 | 結果・時間差 |
|---|---|---|
| 児童手当の手続き | `apply_child_allowance` | 次の暦月処理で申請を登録。承認・支払月を経て現金へ。月次の手続き近似で、実自治体の期限・資格判定の代用ではない |
| 保育を申し込む | `apply_childcare` | 各保護者の就業・復職・求職などの利用条件確認、申請、調整、利用を分離。選べば入園する構造ではない |
| 身近な人に頼む | `request_relative_support` | 利用可能性の仮定に基づく返答。利用できればAの保育時間配分へ。実際の祖父母の予定・能力の予測ではない |
| 復職を相談 | `request_return` | 希望時期を登録。産後休業、保育、契約条件が実働を制約。希望時期が確定した給与ではない |
| 時短勤務を相談 | `request_hours` | 75%の時間を希望。雇用先の応答シナリオを経て勤務・給与へ |
| 求職を始める | `job_search` | 求職状態へ。確率的な提案を待ち、届いた提案のみ受諾・辞退できる |
| 仕事の提案を受ける／見送る | `accept_job_offer` / `reject_job_offer` | 現在の提案IDと一致したものを処理。受諾条件が勤務・収入計算へ |
| 生活費を抑える／通常／余裕 | `set_spending` | 調整できる生活費の予算を基準の80/100/115%へ。家賃や返済を勝手に下げない |
| 不足時に預金・証券を使う | `set_liquidity_policy` | 保有資産がある家庭で支払いに使う資産を指定。資産振替であり新たな収入や投資益ではない |
| なだめる／そばで見る | `B.act`（仮説効果OFF） | その場の観察報告と履歴を追加。気質・能力・愛着の永続的加点はしない |
| 方針を変えず続ける | 新体験層の3か月保留 | 選択履歴と保留期間を残す。ネイティブAの問題は保持。自動処理で解消したことにはしない |

退職、育休延長、転居、投資、住宅ローンの借換等を常設の選択一覧へ増やしてはいない。既存APIで操作可能なものでも、家庭・状況に沿った選択導線と結果を用意していないものはP1/P2へ残す。

## 自動で起きることと文章の根拠

出生からの日付・発達・観察の生成、Aの給与・給付の入金、生活費・家賃・税等の支払い、申請の返答、保育・就業状態の変化が既存エンジンから生じる。これらを、月次の短い記録へ変換する。選択をしなくても通常の身体・発達更新は進む。

子どもの各文章は、親向け観察APIで真となった行動に限って用意する。観察報告ハッシュ・行動名・真値を保存し、内面や未観察の能力を追加しない。「ひとりで足を運ぶ」はその報告がある場合だけで、月齢から歩けたことにしない。

親の呼び名、居間、時刻、赤い布、家計記録を開く仕草はユーザーが許可した日常の演出。`fictional_staging` と画面の注記で区別する。実在する園の名前、特定の言葉の発声、病気、診断、家庭外の新人物の支援、修理費などは創作していない。自由文生成APIを使わず、構造化事実を有限のテンプレートへ変換して追跡可能にした。

## 検証

結果は `reports/integration_verification.json`、`reports/browser_verification.json` と保存後の `C01_RELEASE_VERIFICATION.json` を正とする。

- 10家庭：都心・郊外・低密度、単親、就業・職業・学歴指定、現金0・1,000万円、兄弟のいる家庭、月途中出生を含む。実際のA/Bで24か月。通常24期、月途中25期、ID・会計・観察根拠を検査。
- 3家庭の生活費方針比較：現金、未払い、発生費用に実際の差が生じる。現金0同士でも未払額に差が残る事例を隠さない。同じ比較で子どもの内部状態が一致し、未識別の能力効果を足していないことを確認。
- 保存・復元後の状態・次期の完全一致、破損拒否、表示の乱数不消費、旧Gameとの科学状態一致、親向けAPIの潜在状態不含有。
- Chromiumで通常の設定から開始し、実時間の10秒進行、倍速、停止、文脈選択、保存・ページ再読込、24か月到達。1366×768で全体スクロールなし。画面とプレイ履歴を保存。
- 旧C-0の13テストを実行。A/Bの旧実装を改変して互換性を作ったわけではない。

これらは開発者によるシナリオ検査であり、実ユーザーの面白さ評価ではない。未校正の行動分布や家計が現実へ適合したという検査でもない。

## 研究上の未解決部分と、体験上の残り

**研究上**：Bの気質・行動・関係性の外部校正は未完了。Aの雇用継続・実働0・無給経路、家計の同時分布、保育選考、税精算、自治体制度の未適合を継承。返答確率・親族支援・時間割当には仮定がある。育休給付等の適格性は推定。開始時の年収分布は過去資料の移送で、2026年の実測新生児世帯同時分布ではない。

**ゲーム設計・表現上**：場面は観察可能な10種ほどの行動を中心としており、24か月の文章・反応の幅はまだ狭い。睡眠・授乳・離乳食・健診・健康の生活生成が不足。子どもへの関わりは観察機会として働くが、長期の関係性は変えない。予想外の生活事件や親自身の人生の幅は限定的。同じ未解決の就業問題が再び相談になる。児童手当の申請期限など日次の切迫した判断は、現行の月次近似では十分に扱えていない。

P1は、この版への実プレイのフィードバックを受け、場面別の子どもの短期反応、生活リズム、給付・保育・復職の相談を優先する。選択と結果の記憶を家族の文章へより自然に持ち越す。P2の多様なキャリア、資産形成・住宅、長期関係、2歳以降、社会変化は保持するが、P0の評価前に増やさない。

## 現在どこまでゲームとして成立したか

自動で流れる生活を一画面で眺め、家族の条件から生じた相談へ意思を反映し、実際の家計・仕事・保育・観察の変化を確認して24か月を残す、という操作可能な循環が成立した。画面のタブを探して手動更新する負担を取り除き、集計数を主役にせず場面へ変換した。

一方、子どもとの関係が深まる実感や毎月の生活の豊かさが十分かは、まだ実ユーザー評価を待つ。今回成立したのは「自動生活・状況別の選択・実状態への反映・記録」であり、20年の人生、臨床的妥当性、万能な親子相互作用ではない。

不足はUIの導線だけではなく、子どもの場面別行動と観察表現、親子相互作用の根拠と実装、Aの就業・保育の未解決経路にある。2〜6歳へ広げる前に、このP0を実際に遊んでもらい、ログの反復、子どもの存在感、相談頻度と選択後の納得感を評価し、根拠の薄い大きな効果を足さずに改善するべきである。
