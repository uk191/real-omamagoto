# C-3.1 構築・検査報告

対象：C系統改善第1弾「強制選択イベント」。作業日2026-10-19（日本時間）。面白さの最終判定はユーザー本人によるプレイで行う。

## 変更の範囲

四つの相談構造（経験／興味／仕事と家の時間／予想外の機会）を実装した。各四択は別の価値観、実際の行動、時間・費用・記録・持越し予定を持つ。通常の相談時期は生後4・8・12・16か月、その約二か月後に実際の結果を参照する後続相談が出る。単なる同梱・文章分岐ではなく、既存C3活動と均衡仕訳、Aの勤務・支出・保育・支援希望に接続した。

既存Aから本人宛ての求人が実際に届いた場合は、Cの構造をその提案の返事へ適応させる。新しい第五ジャンルを増やすのではない。提案が早く届けばCの登場も早まる。受諾・辞退・支援の相談等を既存Aへ送り、希望と結果を区別する。単純に旧セレクターを外すだけで求人への返答ができなくならないよう、実際に求人が出るseed5503で四分岐を追加検査した。

表示層・相談構造／実行記録・A/B本体を分離した。新規 `27_experience_c31` は `26_experience_c3` の継承クラスで、既存A/B/C3コードや統計核を編集していない。通常の六つの生活方針、自発的な楽しみ、アルバム、段階ログ、時計、速度、保存を継承する。置き換えるのは旧版の一般的な強制選択セレクターであり、今回の相談に旧イベントを大量に追加して混ぜない。

年齢・学歴・地域から所得／職業を生成できるよう通常UIを修正した。所得と初期現金の上書きAPIは互換性のため残すが、画面に入力欄を出さない。初期資産の問題には任意の上限で対処せず、別報告 `INITIAL_ASSETS_AUDIT.md` に原因と残る影響を示す。

## 結果の構造

`case_ledger` が選択・価値・犠牲・前後状態・約束ID・後続親IDを記録する。`commitments` は実行日・状態・時間・口座差分・家族ID・経験・仕訳・申請・未実現理由を持つ。購入物と反復経験は既存inventory/experiences/scenesへ、家族の記録はkeepsakesへ保存する。旅費メモと匿名／公開応募の結果も保存対象。途中保存でも同じ結果になる。

プレイヤーには心理の内部値や未来の発達時期を出さない。長期の能力・人格・愛着を上下させる追加処理はない。反応・合意・天候・架空企画の抽選・価格・移動条件・計画時間枠にはゲーム用仮定がある。Aの就業・保育・家計の外部未検証部分もそのまま。モデル内部で変化することと、現実の因果効果の識別は別である。

## 検査データと読み方

- `reports/regression_baseline.json` / `regression_updated.json`：共通の家庭生成・主人公・ID・時計状態・段階ログ・停止再開・保存完全再現・24か月・口座恒等式の検査。
- `reports/sixteen_branches.json`：同一チェックポイントから全16分岐、直後・一か月後・三か月後・後続の実行。読むための比較は `SIXTEEN_BRANCHES.md`。
- `reports/varied_households.json`：追加5家庭の24か月、単親・月途中出生・年齢学歴・移動条件の差。全国大量試行ではない。
- `reports/individuality.json`：A家庭を固定しB子どもseedだけを変えた3人。A口座を保って反応列が異なる。
- `reports/native_job_offer.json`：実際のA求人に対するC四分岐。
- `reports/browser_baseline.json` / `browser.json`：実Chromiumの時計・操作。新版は二家庭24か月、各8相談、停止・選択・再開・保存・読込、狭い画面。最終ブラウザ検査には使用コードのSHA256も保存する。
- `reports/connections.json`：ブラウザの先行空接続があっても処理でき、古いrevisionの重複操作を拒否する。
- `reports/legacy_api_tests.txt`：旧C0 APIの13テスト。
- `reports/screenshots`：四つの主相談・後続・結果・24か月・アルバム・狭い画面。

これらは開発者の自動シナリオ検査であり、実ユーザーテストや科学的外部校正ではない。識別子と文面を除外して支出・振替・時間・活動種類・申請・応募形式等を比較し、四分岐が別の結果を持つことを確認する。反応だけがランダムに変わることを選択の効果とは数えていない。

## 保全・配布・保存後の検査

新しい環境には最初READMEだけがあったため、公開済みC3をSHA256とZIP CRCで確認して復元した。原本は `/workspace/c31_baseline` に保持し、固定公開URL・ハッシュを `inputs/BASELINE_RESTORATION.json` に記録した。配布パックでは旧C3の全app/runtimeをそのまま継承し、新規C31を別パスへ追加する。

5GB超の過去研究原本は今回の環境に全復元していない。その保存後独立検査まで行ったとはしない。動作に必要な旧統計核・地域SQLite・APIを保全・再検査した範囲に限定する。

`C31_CODE_AND_REPORTS.zip` は本版のコード・資料・小さい検査結果・画面・再構築手順。`C31_COMPARISON_DATA.zip` は全16分岐と追加家庭の詳細。旧原本を各版に複製しない。`C31_PLAY_WINDOWS_X64.zip` はユーザーが遊ぶために旧ランタイムと実行用DBを含む約103MBの単独パック。小さな `C31_START.zip` がこれを取得し、SHAと全ファイルを検査して別フォルダへ用意する。

`C31_player_distribution/verify_release.py` は保存したZIPを別場所に展開し、全マニフェスト・旧ファイル一致・SQLite整合性／外部キー・旧新API・イベント停止時の保存再開・再現性・24か月・プレイヤー情報分離を新しいPythonプロセスで調べる。`C31_RELEASE_VERIFICATION.json` と `C31_SHA256SUMS.txt` が最終検査記録。

Windows用のDLL・Pythonランタイムは旧版のバイトを維持する。起動補助の展開・ハッシュ検証・欠落修復・旧セーブ保全・エラーログ・子プロセスエラー処理はLinux上のPowerShellで検査する。Windowsのcmd.exe／native Pythonの実機実行とは区別し、Windows実機検証済みとはしない。

## 残る課題・次の修正判断

最優先はユーザーの四択体験。どの選択で迷ったか、背景が足りたか、直後と後日の違いが伝わったか、家族や子どもに会っている感覚があるかを聞く。本版が実装できたことは、直接の費用・時間・経験と後続条件の違い、観察の個体差、記録の参照である。内面の正確な推定や長期介入の因果予測はできない。

巨額預金により金銭的な犠牲が弱い家庭がある。全世代資産の出生家庭への移送と年齢同時分布は次工程の研究課題。資金や時間が不足し四択すべてが成立しない月は相談を延期するため、すべての開始条件で四相談の登場を保証しない。今回は検査した家庭での動作を確認する範囲である。

勤務・支出・支援の希望は実際のA状態に影響するが、保育や雇用の結果の外部妥当性は未解決。配偶者との合意や反応の校正も残る。支出を減らしたことによる細かな生活品の変化、会場の個別展示、具体的な転職面接、乳児への長期心理効果は未実装。文章だけで実現済みにはしない。

イベントを増やす前に、本版の選択で価値の対立を感じるかを確認する。巨額資産・弱い仕事の背景・単純な反応が体験を阻害する場合は、それぞれ統計モデル／状況設計／行動観測の課題として切り分け、今回のユーザー評価を受けて優先順位を決める。
