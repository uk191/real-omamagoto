# C-2｜低負荷の自動進行と重要判断

2026年10月18日。C-1の多数の常時操作を、持続方針と条件付きの大きな判断へ置き換えた研究体験版。旧研究の外部妥当性を完成したとは扱わない。

## 実装したループ

父親または母親として始め、6方針から一つ選ぶと自動進行する。普段のメイン画面の操作は方針見直し・停止/再開・家計の中身・保存に限定。方針は変更するまで続き、主人公自身の勤務希望、予定枠、買物、外出、預金振替へ翻訳する。配偶者の勤務まで操作しない。重要な判断で選んだ勤務希望は、方針の既定値より優先し、方針を変更するまで保持する。

約10秒の月を3段階に分け、段階1・2でC2の活動や観察を実行し、段階3で旧A/Bを次の実際の暦月境界へ進める。Aの未来forecastは公開せず、判断後の次回stepで希望を反映する。日単位の新しいA経済モデルを作ったわけではないため、見せかけの日付は付けない。途中出生の実日齢、24か月誕生日、最終の未完了会計も区別する。

判断は家計・就業・保育・家族の分担・遊び・旅行・お金の置き場所などの現在条件から候補を絞る。単親に同居配偶者との交代を出さず、旅行は月齢・費用・時間・経験が合うときだけ、仕事の提案は旧Aから実際に届いた場合だけ出す。通常は前回の判断から2〜3か月の間隔を空け、資金や仕事の急な確認は例外とする。これはゲームのペースであり、現実の家庭で問題が発生する確率ではない。

## 方針の実際の違い

| 方針 | 主人公自身の時間・お金・行動 |
|---|---|
| 仕事と収入 | 通常勤務を希望、求職条件なら仕事探し、仕事準備に月8時間まで確保、家で声かけ |
| 子どもとの時間 | 自分の勤務8割を相談、家で過ごす活動を月4回の体験枠へ |
| 遊びと体験 | 月3千円の上限内で絵本・ボール・外出、手元の物を繰り返し使用 |
| 安定した暮らし | 働き方を自動変更せず、家で過ごす活動を中心にする |
| 貯蓄をつくる | 直近の生活支払い参照額2か月分を残し、余剰を月2万円まで定期性へ振替 |
| 家族と交流 | 親子ひろばや分担を優先。配偶者の合意・実行した予定を別に記録 |

資金不足や予定枠不足は未実行として記録。活動の価格・時間・施設・商品・合意の規則はシナリオで、能力・愛着の長期加算はない。

## ログの修正と検査

文の言い換えではなく、構造化した事実の意味キーを日本語化の前に比較する。同じ活動・場面・反応は原則一度だけ。初めての物・場所、反応の変化、反復から初めて分かるパターン、実際の働き方の変化、希望への新しい返答を優先。何もなければログを埋めない。経験は消さず、反復もexperience ledgerに残し、表示だけを抑制する。

最初の監査で、活動の重複を抑えても「選びました」「受け付けられた」という定型文が約14〜32%重複していた。そのため、一般的な選択完了ログを廃止し、移した金額・口座・残った資産や、まだ結果でない手続きの時間など、実際の新事実だけを出すよう修正した。同じ条件への同じ返答も再表示しない。取り置きは追加額だけでなく実際の合計も記録する。

最終5家庭では、24か月の公開ログは25/22/34/28/17件。正規化前の完全同文重複は全家庭0件。活動の意味キーの再表示も0件。全ログにsource_refsがあり、具体物・場所・前の経験IDは実際の持ち物・実行履歴から参照する。自由作文全般の意味理解や、全ての人が重複を感じないことを保証する検査ではない。

## 比較実験

東京・大阪・北海道・沖縄・愛知、年齢・資産/口座・家族人数・主人公・子どもseedの異なる5家庭を24か月進行。単親母、きょうだいのある家庭を含む。口座を明示した試行は実測資産分布への適合例ではなく、資金条件を比較するシナリオ。

重要判断は11/9/10/11/9件。実際の平均間隔は約2.1〜2.5か月。21の判断チェックポイントで同一家庭・同一seedから全選択肢へ分岐し、直後と3か月後の口座、時間、実行した経験・物、申請・希望、結果、後続の判断を保存した。6方針の24か月比較でも、実際の資源配分と経験に全て差があることを確認。

同一子どもでは、異なる方針・判断を通してBの身体・気質・短期状態・発達・睡眠の核が同じまま進むことも確認した。これは未識別の長期環境効果を無効にした設計を確かめるもので、現実の環境が子どもへ影響しないという主張ではない。

全操作のUI口座と内部cashの一致、現金恒等式、C2の純資産恒等式、旧13 APIテスト、判断待ちでの保存・再開、seed再現、GETの純粋性、途中出生を検査。詳細はverification.json、log_audit.json、families_24mo.json、event_branch_comparisons.json。

## ブラウザと体験の判定

父親、単親母親、配偶者のいる母親の3ケースを実際のブラウザで操作する。方針選択→標準時間の途中ログ→月末、停止/再開、家計詳細、保存・再読込、重要判断での自動停止→選択結果→自動進行、24か月到達を確認し、画面とプレイヤー視点の履歴を保存する。通常のメイン画面のボタンは4個。小さな操作一覧を毎月処理する必要はない。

これは開発者によるシナリオ検査。**「迷わない」「面白い」「没入できる」という実ユーザー評価は未実施**。実装要件の検査通過を、その評価の完了や改善の証明とは呼ばない。次はユーザー本人にプレイしてもらい、判断の間隔、ログの密度、結果の理解しやすさを評価する。

## 未完成・未識別事項

- 初期資産の年齢・所得・住宅・負債の同時分布は未校正。高額資産を説明する過去の物語は生成しない。
- Aの無給契約継続、保育選考、税精算、自治体参照額、制度年度外の凍結等を継承。未解決のA判断は月次履歴へ残す。
- 短期行動の数値係数、観察感度、配偶者の希望・合意は未校正のシナリオ。心理尺度や愛着診断ではない。
- 実在の施設の場所・予約、リアルな旅行商品・価格、健康・事故の発生率、住宅転居費・敷金、銀行解約条件・運用益は未実装。見せかけの選択や架空の重い事故・借金で補っていない。
- Bの体格や未観察の発達、食事や疾病の領域などは内部進行に留まるものがある。全研究変数を活用済みとは扱わない。対応表で区別した。
- C2は旧セーブの自動変換をしない。旧版とその記録は保持し、旧版から再生できる。
- Windowsネイティブの今回の実機検査は未実施。Linuxのブラウザ・PowerShell検査、ユーザーがC1で起動できた方式の継承とは区別する。

2〜6歳の拡張より先に、今回の少数判断のループの実ユーザー評価を行う。研究課題（資産・雇用・保育・行動校正）と、体験課題（判断の明快さ・新情報の密度・子どもの存在感）を別に追う。

補足検査：実際のA求職経路から届いた求人（seed3201）について、受諾/見送りを同じ状態から分岐し、3か月後の雇用契約と給与等が異なることを確認した（job_branch.json）。同一家庭・同一方針で子どもseedだけを変えた12か月比較でも、家計は同じままB潜在状態と実際の反応・観測記録が異なることを検査した（individuality.json）。
